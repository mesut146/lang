//Two parameter kinds, decided by the declared type:
//- `Expr` is a *syntax slot*: every reference to it in the body is replaced by a
//  copy of the argument expression, and the body is copied per call site, so
//  `macro swap(a: Expr, b: Expr){ let t = a; a = b; b = t; }` assigns through
//  its arguments (a twice-used argument is evaluated twice -- if it moves, that
//  is a use-after-move error, not a silent double free);
//- any other type is a *value* parameter: bound once, in declaration order and
//  type-checked, by `let p: T = <arg>;` at the top of the expansion. It behaves
//  like a local of the expansion (assigning to it does not touch the caller, a
//  move type argument is moved into it) and it is evaluated even when the body
//  does not mention it. Since x has no shadowing, the binding uses a fresh name
//  when the parameter's name is already live at the call site, so `take!(s)`
//  never collides.
//Hygiene: the names the *body* declares are alpha-renamed per call site, so a
//macro may use `t`, `i` or `res` whatever the caller has in scope, and a
//substituted argument cannot be captured by a body local of the same name (a
//body local may even reuse a parameter's name: from its declaration on the name
//is the local, before it the parameter). A name the body never declares (and
//that is not a parameter) is a *free* name: it resolves at the call site, like
//before, but if the caller has a local of that spelling the expansion is an
//error ("resolves to a local at this call site; pass it as a parameter") --
//reading caller state must be explicit (tests/fail/macro_capture_local.x). A
//nested binder's spelling keeps its fresh name for the rest of the body (no
//scope restore), so keep inner binder names distinct from outer uses.
//A body ending in an expression makes the macro an expression of the inferred
//type (`macro square(x: Expr){ x * x }`), otherwise it is void.
//slice 4 (2026-10-19, doc/codegen_macros.txt phase A): a *list* parameter
//`macro m(xs: Expr...)`: it must be the last parameter (one per macro), takes
//every remaining argument (zero or more, so `m!()` is legal) and is not a
//value: inside `$( <statements> )*` the current element is `$xs`, and any
//other use of the bare name is an error ("list parameter 'xs' must be used as
//'$xs' inside $( ... )*"). The repetition emits its statement list once per
//element, in place (also inside a nested block), and the body is copied again
//per iteration, so per-iteration hygiene is the same alpha-rename as above
//(two iterations may each declare `t`). One level only: `$(` inside `$(` is
//an error, and `$name` outside a repetition is an error
//(tests/fail/macro_repeat_*.x). In an *expression list* (call arguments, array
//elements, tuple elements) the repetition is `$( <exprs> ),*`: the elements are
//repeated per list element and the enclosing list supplies the commas, so the
//list's own separator follows the repetition -- `($( $xs ),*, 99)` is the
//elements plus 99, `($( $xs ),*)` is a parenthesized repetition. A
//single-value position is an error ("only valid as an element of a list").
//Lookup follows the same rules as any other name: a bare `name!` reaches
//top-level macros of this unit and, through `use` prefixes (every `mod` is
//registered as one, as for types), the macros of its modules -- `use m;` or
//`use m::{name}` spell that out -- plus the macros of imported units; a scoped
//`m::name!(...)` (or `a::b::name!`) matches the module the macro was declared
//in, including a module of an imported unit. One `macro name` per unit,
//parameter names must be unique and the builtin names
//(`format`/`print`/`panic`/`debug_member`) are reserved.
//Still open: full definition-site resolution of free body names -- a name the
//macro's own unit declares but the caller also has (a global, a function, or a
//unit-level item of a same-named import) still resolves at the call site. The
//caller-*local* half is closed above. Name visibility is unaffected: the
//expansion still runs with the caller's imports plus the defining unit's
//(extra_imports).
//Code-generation macros have their own design note now: doc/codegen_macros.txt
//(declarative list parameters + `$( ... )*` repetition; no CTFE, no token-tree
//matcher; item position and fragment kinds phased behind it). The unused
//TokenStream/#derive_macro stub is still described in doc/token_macros.txt.
//The narrow
//`use m::{name}` list form round-trips through the formatter (tests/fmt/macro.x).
