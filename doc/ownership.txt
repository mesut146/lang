Ownership / auto-drop mechanism notes (established Oct 2026, all
proven through strict-triangle validation + IR inspection).

Drop-ness is structural: DropHelper recurses struct/enum fields, so any
type containing a String (Variable, Rhs, RType, CStr, Option<Drop>...)
is a drop type. is_struct() covers every drop type (prims/pointers/
lambdas/str/slices are never drop). Consequence: every owned value the
analyzer can name is auto-dropped somewhere; manual drops only survive
where the analyzer cannot name or must not fire.

Where auto-drop fires (all verified):
- Named locals: drop_var at scope end (ownership.x).
- Call-result temps: add_obj registers exactly four shapes
  (backend/expr_emitter.x): &temp materialization (visit_ref rvalue),
  arrays, struct-typed calls (visit_call2), struct literals (visit_obj).
- Reassignment: store() routes every drop type through drop_lhs
  (ownership.x), which frees the overwritten live value. Skips MOVED
  (heal pattern), moved-partial, explicitly-dropped places. Hardened to
  return (never panic) on untracked EXPR shapes and unregistered vars.
- Jumps: do_return / do_continue / do_break emit for live vars+objects
  (get_outer_vars_loop includes OBJs, stops at the loop boundary).
- Loops: per-iteration emission inside the body, IR-proven for while
  AND for-each (a `let s` temp drops inside while_then/for-body, once
  total -- no scope-end duplicate).

Move = shallow copy. The callee frees the heap once; the source keeps
dangling bytes that must be heal-overwritten before anyone reads or
drops them. MOVED marks suppress every auto path (drop_var, drop_obj,
drop_lhs), which is why heal-assigns must skip and why test 17's
deref-heal phase expects single counts, not doubles.

Manual drops that remain (all load-bearing, do not strip):
- impl Drop for Own (Logger::exit flush has no relocatable site, and
  its body touches self so B2 skips it anyway).
- Drop-derive codegen string (derive.x: generates source, not memory).
Deleted as redundant (derived glue proven): impl Drop for String
(List frees its buffer), Protos and Context (pure field frees;
RSS-compared, no leak signal).

B2 rule (impl Drop augments): a manual Drop body runs first; then
derived glue frees the drop-typed struct fields the body does not
already handle. The scan is PER-FIELD: naming a field (self.f...) marks
only that field handled (its derived free is suppressed); anything
rooted at bare self (self, self as T, &self, self passed as an argument,
a lambda capture) marks the whole body manual and suppresses every
derived free -- a free can hide behind a whole-self helper. Rationale:
touching a field is easy to detect syntactically (Name/Access/casts/
index/literals/infix/lambda shapes walked recursively); freeing is not.
So per-field is conservative in the safe direction and never frees less
than the old "any touch -> suppress all" rule: side-effect-only customs
gain recursion, and a body that handles one field still lets the others
drop. Idempotent (an appended `Drop::drop(self.f)` names f, so re-runs
skip it). Structs only; enums keep full manual responsibility. Proven by
tests/own/19wrap (custom print + unfreed field drops exactly once) and
tests/own/22b2partial (body frees one field, the other still drops).
Incidental finding while proving this: bare blocks don't scope drops
(locals die at function end), so drop-count tests must use function
boundaries.

Extern aliasing (CLOSED with #[returns_alias], tests own/18alias +
fail/returns_alias_*): legal callees cannot return owned aliases of
borrows, but extern bodies cannot be checked. An annotated param
`#[returns_alias(p)]` declares the return may alias that borrow; at
each call with `&o` in that position the owner is consumed (post-uses
error, scope end skips its drop) and the fresh return drops normally.
Non-borrow or unresolvable args are a loud error; non-heap owners pass
through. Over-claiming on plain fns is allowed but conservative (owner
consumed anyway). Limitations: direct calls only (no fn-pointer/
lambda attr lookup), `self` not nameable, pointer-var forwarding
`f(p)` rejected (no points-to info -- pass `&o`).

Removal rule (used for 164 stripped): a manual drop may go iff its
value is a named drop-typed place (or registered object) that is dead
after the call, with borrows-only uses. Reassign sites need no manual
(drop_lhs covers); EXPR-shaped lhs keeps its manual. Anonymous call
temps (remove().drop()) are covered by add_obj + *self-receiver move
marking -- they went too (anonstrip).

Validation limits: suite + MALLOC_CHECK_=3 catch doubles loudly but
are LEAK-BLIND. Every strip batch additionally needs an IR or
drop-count argument (A-tracker in tests/own/common.x, check_ids) that
the freed value still dies exactly once. Per-batch triangle (previous-
release build, suite, heap, self-host is the same gate twice -- build
once, validate much) is mandatory; strict catches analyzer fallout as
precise errors, self-host catches builder divergence (closed:
1.05/v1.14/v1.11 agree).

Valgrind ledger (Oct 2026, v3.22, x86_64):
- User programs: 9/9 drop-count tests report 0 bytes at exit. Ownership
  soundness proven where it matters.
- Discarded macro results (format()/`?` in statement position) and
  non-matching if-let temporaries: FIXED (b0e399e; tests/own/20,21 +
  tests/leak/* + bin/test.sh leak gate). Same-pass fixes: Box::unwrap
  frees its cell (Drop delegates; hashmap::rehash drops its manual free).
- Elided `Drop::drop(arg)` argument: FIXED (db58ca6; tests/leak/
  box_nondrop.x). When the argument type had no drop glue the emitter
  emitted no call at all, skipping the argument expression -- but
  `Box<T>::drop` is `Drop::drop(self.unwrap())` and unwrap frees the
  cell, so every `Box<T>`/`Ptr<T>` with a glue-less payload leaked it
  (regression from b0e399e, which moved `free` from `Box::drop` into
  unwrap). Fix: visit the argument in both elision branches.
- HashMap rehash orphans: fixed (consumed chain boxes freed; 14KB
  definite + 5KB indirect on the hashmap test went to zero).
- Mutex<T> payload: FIXED by per-field B2 (tests/leak/mutex_payload.x;
  tests/own/22b2partial). `Mutex<T>::drop` names only self.lock, yet the
  old rule suppressed the derived free of `val` too, so every
  Mutex<String|List<..>> leaked its payload buffer (400B in
  tests/std_test/20_worker.x, whose todo queue is Mutex<List<Job>>; the
  10B/40B reps in tests/leak). 20_worker is valgrind-clean now.
- str::real_len empty-string read: FIXED (tests/leak/empty_streq.x). It
  did `self.get(self.len() - 1)`, i.e. buf[-1] for an empty slice, a
  1-byte OOB read before the (0-size) buffer; String::eq with an empty
  operand hits it (HashMap<String,..> key vs a default key). The gate is
  valgrind's error exit, so it catches the read, not a leak. It fired
  inside the compiler too, while compiling a module.
- LLVM graph (~4MB, Function::Create rooted at never-disposed module)
  and static-init tables: by design, undisposable, ignored.
- CLOSED -- bootstrap artifact, not a source leak (db58ca6): the ~38KB
  Type::clone/format records opened after b0e399e. Codegen for the
  compiler's own modules (e.g. `Box<ElseScrutinee>::drop`) is produced by
  the *previous* compiler, so a new compiler built by a pre-fix release
  still leaks internally while its source is fixed. Same source, three
  bootstrap rounds: v1.15 -> S1 = 11 definite records (7 artifacts, incl.
  the 24B ElseScrutinee); S1 -> S2 = 4 (LLVM-internal only); S2 -> S3
  byte-identical. Rule: judge compiler-internal leaks only on a binary
  whose objects were generated by an already-fixed compiler (two
  rounds). The starter shapes that were ruled out by valgrind-clean
  minimal repros (`?`-discard of an enum/struct-wrapping-enum payload,
  Option<enum> discard, HashMap replacement-return discard, inline
  format(..).str() argument) remain clean; the one real leak the chase
  did surface is the elided-argument bug above.
- Compiler-internal roots: NONE left in compiler code. On a normal
  program (tests/normal/19-match.x) and on a full 25-file module compile
  (src/std), every definite/indirect root that valgrind reports is
  LLVM-internal (LLVMContext/Module/TargetMachine/IRBuilder/DIBuilder,
  never disposed in a one-shot compile). Total definite bytes are
  LLVM-only (654KB / ~5MB respectively); no double-free or invalid
  free/read in either. The compiler's own manual drops (Own) name every
  field, so per-field B2 leaves them untouched.
- Parallel compile path (`-j`): two pre-existing bugs (v1.15 has both),
  both FIXED:
  * every `-j` build failed. `Compiler::make_compile_job` closed each
    job child with `eat_close` (pclose) without draining its stdout;
    glibc pclose closes the read end *before* waitpid, so the child --
    which always prints "compiling ..." -- died with SIGPIPE and the
    job reported "failed to compile" + exit(1). A bare C
    `popen("echo hi","r"); pclose(f)` reproduces (rc=13); the read is
    what matters (`popen("echo hi >&2","r")` is fine). Fix:
    `read_close()`, the idiom every other Process::run site already
    uses. Regression: `inc_all` now also builds tests/incremental_test
    with `-j 4` (fails pre-fix).
  * the job arg then leaked. `CompileArgs` (owns `file: String`) is
    boxed by the worker into an `Any`; Any auto-drop is type-erased, so
    the file clone leaked per job (valgrind `-j 4` parent: 81 B / 3
    blocks rooted at `List<u8>::clone <- String::clone <-
    compile_dir_thread`; 0 after). Fix: the Any drop glue below.
- Any drop glue (std/any.x): `Any` gained `drop_f: func(i8*) => void`,
  run by auto-drop before the box shell and type string are freed (so
  auto-drop stays total). The language cannot materialize T's glue at a
  generic site -- a generic function reference (`g<T>`), a generic
  method reference (`G<T>::m`) and a generic lambda are all rejected
  (verified) -- so the *constructing* site hands it in:
  `Any::new<T>(v, glue)`. `Any::new<T>(v)` keeps a no-op glue (payload
  innards still need `drop2<T>`, unchanged). `Worker::add_arg_heap<T>`
  is the worker-side form; the compiler boxes each job with
  `release_compile_args`. Regressions: tests/own/23jobarg.x (A-tracker:
  the boxed arg drops exactly once) and tests/leak/any_payload.x
  (valgrind: the payload's String buffer is freed). Both fail to
  compile pre-fix.
- Manual-drop sweep (2026-10-18, on `own-strip-manual-drops`): the
  hand-written explicit drops outside `impl Drop` bodies (and
  `Any::drop2`) were removed -- 27 sites, 7 files. Two families: (a)
  "free a local/param before returning" (fs.x 8, ops.x 6, printer.x 4,
  map.x get_pair_or 2, hashmap.x 2, formatter/main.x 1); (b) "drop-old +
  std::no_drop(place) + assign" (map.x add 2, option.x set/reset 2).
  Auto-drop already owns both, so removal is a no-op: (a) owned locals
  *and* owned params drop on every exit path, including early `return`
  and `return` from inside a loop (IR: `String__drop_String`
  immediately before each `ret`, for a local and for a param alike);
  (b) drop-on-assign fires for `p.f = x` and `*p = x`, concrete and
  generic struct fields and enums (IR: `..__drop_..(&p.f)`,
  `G__drop_G(p)`, `Option<..>__drop_Option(..)` immediately before the
  store). The one place form it did not cover at the time -- the
  explicit deref member, `ptr::deref!(p).f = x` (untracked -> leak) --
  was closed right after (next bullet); none of the swept sites used
  it. The only manual drop left outside
  `impl Drop` bodies is the type-erased `Any` glue
  (`release_compile_args`, backend/compiler.x) -- by construction it
  cannot be auto-dropped. Regression: tests/own/24ptrassign.x pins the
  overwrite shapes (pointer-field, pointer-deref, Map::add same-key,
  get_pair_or hit) via the A-tracker. Full suite green on S1 and S3
  (normal pass=63 xpass=0, fmt/leak/opt pass); triangle S1==S2==S3
  byte-identical (source-level change; codegen logic untouched).
- `ptr::deref!` member place (2026-10-18, same branch): the sweep above
  flagged `ptr::deref!(p).f = x` as the one shape drop-on-assign did not
  cover (untracked -> leak). Cause: `Own::drop_lhs` bails when
  `Rhs::new(lhs)` is `Rhs::EXPR`, and `Rhs::new` types a field place
  only when its scope carries a variable handle -- which the
  `ptr::deref` macro's RType does not (`visit_macrocall` returns a bare
  `visit_type`; resolver.x:2872). `p.f` and `*p` carry a `vh`, so they
  were fine. Fix: `Rhs::new` sees through a `ptr::deref!` scope, so
  `ptr::deref!(X).f` names the same place as `X.f` (`FIELD{X, f}`).
  Because `drop_lhs` and `do_move` share that key, a live old value
  drops on assign (leak gone) and a value moved out first
  (`let o = ptr::deref!(p).f;`) is marked moved, so the heal assign
  drops nothing (no double free). Bare `ptr::deref!(p)` (whole value)
  is unchanged: still EXPR/untracked. Regression:
  tests/own/24ptrassign.x cases `deref_macro` (leaked pre-fix) and
  `deref_macro_move` (exactly once with heal). Full suite green on F1
  and F3; triangle F1==F2==F3 byte-identical.
- Field of an owned temporary, `f().field = v` (2026-10-18, same
  branch): `drop_lhs` bailed on any `Rhs::EXPR` place, so assigning to a
  field of a call-result temporary leaked the overwritten value
  (verified: probe `mk().s = format(..)` leaked the `String` built in
  `mk`; valgrind 10 bytes definitely lost, no drop before the store).
  Fix: `drop_lhs` now recognizes a field of a registered temp *object*
  -- an owned temporary the engine already drops at scope end.
  `place_root` descends nested field accesses to the base expression and
  `drop_temp_field` matches it against the scope's objects (mirrors
  is_temp_scrutinee's walk); the field is live by construction, so the
  old value drops at the assign while the temporary's own drop later
  frees only the new value (exactly once). Other untracked bases (bare
  `ptr::deref!` of an untracked place, extern results) keep the silent
  no-op. Regression: tests/own/25tempassign.x (direct + nested; fails
  pre-fix: assertion 0 != 1). Full suite green on FIX1/FIX3; triangle
  FIX1==FIX2==FIX3 byte-identical.

- Arrays and tuples as owners (2026-10-18, same branch): an array or
  tuple value whose element type needs dropping crashed the compiler --
  `drop_force` (backend/emitter.x) called `get_drop_proto`, which does
  `get_decl(rt).unwrap()`, and an array/tuple has no decl ("unwrap on
  None", option.x:26). Reported with an array *literal*: `let x =
  [String::new("a"), String::new("b")];`. Fix: `drop_force` drops an
  array/tuple element-wise and recurses (so nested aggregates work);
  the element count is a compile-time constant, so the loop is unrolled
  (straight-line code, no new basic blocks, no control-flow
  interaction). The literal emitters (expr_emitter.x) also had to mark
  each element source moved (`do_move`, mirroring `set_fields`); without
  that every source temp was dropped a second time (valgrind: the same
  allocation freed twice). Two adjacent holes were closed while making
  the feature reachable: `[e; n]` with a drop element type is now a
  clean error ("repeated array element type needs dropping") -- it
  copies one value into n slots, i.e. n aliases freed n times; and a
  move out of an index place (`send(arr[0])`) is refused ("cannot move
  out of an array element") -- index places are untracked, so the array
  would drop a value that already left. `check_partial` also learned
  tuples (decl-less) instead of panicking in `get_decl`, so partial
  tuple moves follow the struct rule (every drop element must move:
  `send(t.0); send(t.1);`). Regression: tests/own/26arrtuple.x (array
  literal, array of structs, nested array, tuple, whole-array pass,
  tuple partial move; pre-fix it does not compile) plus
  tests/fail/array_elem_move.x and tests/fail/array_repeated_drop.x for
  the two diagnostics. Array-element overwrites stay untracked (silent
  leak, as before). Full suite green on F1/F3 (`normal pass=66 xpass=0`,
  own/fmt/leak/opt pass); triangle F1==F2==F3 byte-identical.

- Aggregate *fields* as owners (2026-10-18, same branch): `derive.x`
  emits `Drop::drop(self.f)` for an array/tuple field (`is_struct` is
  true for both), which used to fail to resolve -- a decl-less type has
  no Drop impl ("get_impl type not covered: [String; 2]"). Resolution
  now returns void for an array/tuple argument of `Drop::drop`
  (resolver.x), and the emitter's `Drop::drop` case drops the argument's
  elements in place (`drop_force` on the argument's address) and records
  the argument moved (`do_move`) like the normal arg path
  (expr_emitter.x). The move mark is what keeps an enum variant field
  from being freed twice: the generated drop binds the payload to a
  local that the engine auto-drops at arm end (own_visitor.x mirrors the
  mark for arm merges). `Resolver::is_cyclic` also panicked on a tuple
  field (`get_decl(tuple).unwrap()`, "unwrap on None"); it now recurses
  into tuple elements like it does for arrays (`Type::is_tuple`).
  Regression: tests/own/27aggfield.x (struct array field, tuple field,
  nested array field, enum variant array field; pre-fix it does not
  compile). A *self-referential* aggregate field (`struct S{ t: (S,
  i32); }`) still overflows the stack in `DropHelper::is_drop_type` --
  pre-existing, invalid type (should be a clean cyclic-type error).

- Array elements as places (2026-10-18, same branch): three holes, one
  shape. (1) `arr[i] = v` never dropped the old element: `drop_lhs` only
  knew struct fields, so an index place fell through as an untracked
  expression -- a plain leak (valgrind: "definitely lost" with String
  elements; the A-tracker showed the old element never dropped).
  `drop_lhs` now drops the overwritten value for any place rooted at an
  index (`arr[i] = v`, `arr[i].f = v`, `arr[i].f[0] = v`), consulting the
  element's state first so an overwrite into an already moved-out element
  is a no-op (`Own::is_index_place` / `Own::index_root`). (2) a *constant*
  index into a local array is a tracked place now (`Rhs::INDEX{scp, idx}`,
  built by `Rhs::new` only for an `Expr::Name` base of array type with a
  literal index), so `send(arr[0])` works: the element behaves exactly like
  a struct field -- moving one out suppresses the array's own element-wise
  drop, and `check_partial` then requires *every* drop element to move (the
  all-fields rule; it enumerates array slots via `Rhs::INDEX`). Reassigning
  a moved element revives it, as for fields. (3) `for x in <array>` used to
  fail outright ("get_impl type not covered: [i32; 3]"): the desugar calls
  iter/into_iter on the array type, which has no impl.
  `Resolver::visit_for_each` now iterates a slice *view* of the whole array
  (`arr[0..N]`); a pointer to an array is dereferenced first
  (`(*p)[0..N]`, never `p[0..N]`, which is a slice of the temporary pointer
  and dangles). By value this copies elements, so a drop-typed element type
  errors exactly like it already does for slices; by reference (`for x in
  &arr`) each `x` is a pointer into the array. Slices, List and Range are
  passed through unchanged (the slice impls live in `std/it`, so the import
  is still required, exactly as for slices).
  Still refused (no place state, so the aggregate would drop a value that
  already left): a dynamic index, a slice, a pointer base, a nested array,
  and a *field* of an element -- `send(p[0].a)` used to compile and drop
  that field twice (`A::drop 1` twice); it is now a clean "cannot move out
  of an array element" (`Own::do_move` refuses any index-rooted place that
  is not `Rhs::INDEX`).
  DECISION (user, 2026-10-18, do not relitigate without asking): runtime
  indices are deliberately NOT tracked. A static key -- local array name
  + literal index -- is the boundary of place tracking; a "runtime index"
  variant would force conservative whole-aggregate state through
  `get_state`/`do_move`/`check_partial` for little gain, and the current
  clean error is sound (the aggregate keeps owning the element). The
  same boundary is why `for x in <array>` by value over a drop element
  type stays an error (the slice iterator indexes with a runtime `idx`);
  iterate by reference instead.
  Regression: tests/own/28arrassign.x (overwrite; field-of-element and
  nested cases), tests/own/29arrmove.x (moves), tests/normal/40-array-foreach.x,
  tests/fail/array_elem_move.x (dynamic index),
  tests/fail/array_elem_field_move.x (field of an element). Residual
  (documented): writing into an element, or a field of one, *after* it was
  moved out is not diagnosed -- the stale value is not dropped (no double
  free) but the new value can leak.

Codegen: for-each `continue` + trailing `return` (fixed 2026-10-18,
tests/normal/39-foreach-continue.x): the for-each desugar ends its
`while(true)` body with the opaque `std::internal_block!(id)`, which
`Exit::get_exit_type` reads as NONE, so a body ending in
`return`/`break`/`continue`/`panic` looked fall-through and the loop
back-edge was emitted after the already-terminated block ("Terminator
found in the middle of a basic block"). Fix: `Emitter::body_exit`
(stmt_emitter.x) sees through the placeholder via the resolver's
block_map. Same lesson as the error-path hang below: an opaque wrapper
must not hide a terminator from exit analysis.

Error-path hang (fixed, tests/fail/format_bad_placeholder): get_line
past EOF spun forever (empty //todo branch). Any from_string snippet
error with the caller's line number -- e.g. unparsable {…} placeholders
-- hung instead of reporting. get_line now returns empty past EOF.
Lesson: error paths need the same termination scrutiny as main paths;
a fail-test pins each newly loud error.
